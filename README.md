# BioTime Auto Consent

Фоновая утилита для BioTime 8 с внешней базой PostgreSQL. После запуска и затем по заданному интервалу она напрямую обновляет таблицу `"Employees"` в указанной схеме. Веб-интерфейса и входящих портов у контейнера нет.

## Что меняется в базе

Обновляются все записи, у которых `"IsHidden" = false`, а `"AllowProcessPersonalData"` равно `false` или `NULL`. Утилита:

- выставляет `"AllowProcessPersonalData" = true`;
- записывает текущее время PostgreSQL в `"DateProcessPersonalData"` и `"LastModified"`;
- фиксирует изменения транзакцией и пишет в журнал количество изменённых записей.

Скрытые записи, строки с `"IsHidden" = NULL` и записи с уже установленной отметкой пропускаются. Если снять отметку, следующий цикл выставит её снова. При ошибке утилита пишет сообщение в журнал и повторяет попытку через заданный интервал.

**Утилита не собирает и не проверяет согласия сотрудников.** Дата в БД отражает время автоматического обновления. Перед включением проверь, что такой массовый режим подходит твоему процессу и что прямое изменение таблицы допустимо для твоей установки BioTime.

## Развёртывание на Linux

Понадобятся Docker Engine, Docker Compose **2.30.0 или новее** и доступ с сервера Docker к PostgreSQL. Compose использует [`env_file` в формате `raw`](https://docs.docker.com/reference/compose-file/services/#env_file), чтобы символы вроде `$` в пароле передавались буквально. Образ собирается локально на базе официального Python 3.12.

До первого запуска проверь на тестовой базе, что в нужной схеме есть таблица `"Employees"` с перечисленными выше полями и что приложение корректно видит изменения. На рабочей базе сделай резервную копию и проверь, как восстановить затронутые записи. Используй отдельную роль PostgreSQL с правом подключения к БД, `USAGE` на схему, `SELECT` на поля из условия и `UPDATE` только на три изменяемых поля. Не используй суперпользователя.

```bash
git clone https://github.com/jamyan/biotime_auto_consent.git
cd biotime_auto_consent
install -m 600 .env.example biotime.env
```

Заполни `biotime.env` на сервере. Указывай значения после `=` без обрамляющих кавычек: в формате `raw` они станут частью значения. Не добавляй этот файл в Git и не передавай содержимое в отчётах и чатах. Доступ к Docker позволяет читать переменные запущенного контейнера.

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `PG_HOST` | Адрес PostgreSQL, доступный из контейнера | Обязательна |
| `PG_PORT` | Порт PostgreSQL | `5432` |
| `PG_DB` | Имя базы BioTime | Обязательна |
| `PG_USER` | Отдельная роль PostgreSQL | Обязательна |
| `PG_PASSWORD` | Пароль роли | Обязательна |
| `PG_SCHEMA` | Имя схемы в БД | `dbo` |
| `AUTO_INTERVAL_MINUTES` | Интервал между попытками, в целых минутах больше нуля | `120` |

Внутри контейнера `localhost` указывает на сам контейнер. Если PostgreSQL установлен на Docker-хосте, укажи доступный из контейнера адрес хоста и настрой сетевые правила PostgreSQL только для нужного источника.

```bash
docker compose config --quiet
docker compose build --pull
docker run --rm --entrypoint python biotime-auto-consent:local -m pip check
```

Эти команды проверяют конфигурацию, собирают образ и проверяют зависимости. Они не подключаются к BioTime.

**Следующая команда сразу запускает обновление записей.** Сначала используй настройки тестовой БД. После проверки останови контейнер, замени настройки на рабочие и запусти его снова.

```bash
docker compose up -d
docker compose ps
docker compose logs --tail=50 auto-consent
```

Проверь журнал первого цикла: запущенный контейнер сам по себе не означает, что база доступна и обновление прошло. При ошибке проверь адрес, порт, имя базы, правила `pg_hba.conf`, права роли, схему и структуру таблицы.

Чтобы применить изменения в `biotime.env`, пересоздай контейнер: `docker compose up -d --force-recreate`. Чтобы остановить следующие циклы, выполни `docker compose stop`. Остановка не отменяет уже зафиксированные изменения: если нужно их вернуть, сначала останови утилиту и восстанови затронутые поля из копии, сохранив прочие изменения в базе.

Для обновления кода останови сервис, скачай нужную ревизию, пересобери образ и повтори проверки. Для возврата к предыдущей версии кода собери образ из предыдущей ревизии; это не откатывает данные.
